# NexusTech Solutions – Security Policy Development & Governance

A practical GRC project demonstrating the design of a structured information security policy framework for a growing cloud-based software company.

## Project Overview

NexusTech Solutions is a rapidly growing mid-sized software development company specialising in cloud-based Enterprise Resource Planning (ERP) systems.

Following significant organisational growth from **50 to 250 employees**, the company identified weaknesses in its existing security documentation. Its five-year-old "IT Rules" document combined high-level security requirements, technical configuration instructions and general recommendations in one document.

As the **Information Security Manager**, the objective of this project was to establish a more structured and maintainable security policy framework that improves accountability, consistency and security governance.

This project applies the **Security Policy Development Lifecycle** to a realistic organisational scenario.

---

## Project Objectives

The project was designed to:

* Establish a clear security documentation hierarchy.
* Distinguish between policies, standards, procedures and guidelines.
* Develop enforceable security requirements.
* Create an actionable user access management procedure.
* Design an employee security awareness and policy rollout plan.
* Establish mechanisms for policy acknowledgement and compliance monitoring.
* Define policy review and maintenance processes.
* Demonstrate practical GRC and information security governance skills.

## Key Deliverables

### 1. Security Policy Hierarchy

Developed a structured documentation hierarchy:

```text
Enterprise Information Security Policy
                │
                ▼
     Topic-Specific Policies
                │
                ▼
      Security Standards
                │
                ▼
          Procedures
                │
                ▼
   Guidelines / Checklists
```

The project also classified eight example security statements as:

* Policy
* Standard
* Procedure
* Guideline

Each classification was supported with a governance-based justification.

---

### 2. Acceptable Use Policy

Created a complete **NexusTech Acceptable Use Policy** addressing:

* Appropriate use of corporate resources
* Prohibited activities
* Reasonable personal use
* Account and credential protection
* Unauthorised software
* Information handling
* Security incident reporting
* Monitoring
* User responsibilities
* Management responsibilities
* Exceptions
* Compliance and enforcement
* Policy review and version control

The policy was designed to focus on **what users must or must not do**, rather than technical implementation instructions.

---

### 3. User Access Request Procedure

Developed a sequential procedure for Helpdesk and IT personnel covering:

1. Request submission
2. Identity verification
3. Request information validation
4. Manager approval
5. Data/system owner approval where required
6. Role selection
7. Least-privilege verification
8. Account creation or modification
9. Permission assignment
10. Security-control verification
11. User and manager notification
12. Evidence capture
13. Ticket closure

The procedure also addresses emergency access, exceptional requests and audit-trail requirements.

---

### 4. Communication & Training Plan

Developed a rollout plan for implementing the Acceptable Use Policy across different stakeholder groups.

Target audiences included:

* General employees
* IT personnel
* Managers
* Human Resources
* Contractors and third parties

The plan includes:

* Key messages
* Communication channels
* Responsible owners
* Rollout timing
* Policy acknowledgement
* Training requirements
* Knowledge checks
* Completion targets
* Escalation for non-compliance

---

### 5. Policy Review & Maintenance Memo

Developed a policy review memo following two significant organisational events:

* Migration of the primary database to **AWS**
* An incident involving the sharing of sensitive information through a personal cloud storage account

The review identified the need to clarify:

* Approved cloud storage services
* Use of personal cloud storage
* Handling of organisational and client information
* Cloud-related security responsibilities
* Policy review triggers

The project also established annual review requirements and early-review triggers for significant changes or security incidents.

## Governance Approach

The project follows a simple governance principle:

> **Policy defines what the organisation requires; standards define minimum requirements; procedures explain how activities are performed; guidelines provide recommended good practice.**

This separation helps prevent the common problem of mixing management requirements with technical instructions in the same document.

## Key Security Principles Applied

### Least Privilege

Users should receive only the access required to perform their authorised responsibilities.

### Accountability

Access requests, approvals and provisioning activities should leave an appropriate audit trail.

### Separation of Responsibilities

Policy ownership, approval, technical implementation and independent review should have appropriately defined responsibilities.

### Risk-Based Governance

Security requirements should consider business operations, information sensitivity, technology changes and identified risks.

### Continuous Improvement

Security policies should be reviewed when incidents, technology changes, audit findings or other significant events demonstrate that changes may be necessary.
